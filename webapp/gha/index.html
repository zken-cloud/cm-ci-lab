CodeMender CI Lab — Public Preview (GitHub Actions)

The same lab as the Cloud Build guide, on GitHub Actions. Scan Juice Shop, verify a real vulnerability, fix it, open a PR. Because a GitHub runner lives outside Google Cloud, it can't pick up a build service account — so cm authenticates with your injected @google.com credentials, billed to the shared preview project cloud-llm-preview1.

⏱ ~40 min ◆ Intermediate ⎇ GitHub Actions ☁ GCP · CodeMender Interaction API
⚠ Staging draft — not tested on GitHub Actions

The interactive path (download → cm init → cm find) is verified in cloud-llm-preview1 with a @google.com identity, and the Cloud Build fan-out scripts were validated against a real binary. This GitHub Actions variant has not been run — the auth wiring below (injected ADC) is written from what works interactively, not proven in a runner. Treat it as the plan.

◆

How it works

One GitHub Actions job on ubuntu-latest does the whole flow — no container, no state bucket. That's the big simplification over Cloud Build:

  • Single job = state just works. CodeMender's SQLite state.db lives on the runner's disk for the life of the job, so find → verify → fix share it with no gcsfuse and no cross-step hand-off.
  • node, git, jq are preinstalled on the runner, and cm verify can build & run Juice Shop there — so there's no toolbox image to build either. You just download the cm binary in a step.
  • Fan-out is still available — scan many files, then verify/fix across findings; each parallel worker gets its own independent clone (not a git worktree — that shares .git and deadlocks). See the caveat in Step 5.
◆

Access model — inject your @google.com credentials

Preview access is a human @google.com entitlement, and a GitHub runner has no way to be you on its own. So you hand it your Application Default Credentials as a secret, and point CodeMender's quota at the shared entitled project.

PieceWho / what
Entitled projectcloud-llm-preview1 — the shared, preview-entitled project. All CodeMender usage bills here.
Calling identityYour ldap@google.com, injected into the runner as ADC.
Quota projectcloud-llm-preview1 — set on the ADC so cm attributes usage to the entitled project.
SecretsCM_ADC (base64 of your ADC JSON) and GH_PAT (to push + open the PR).
⚠ That ADC is a live human credential

CM_ADC holds your user refresh token — broad, long-lived Google Cloud access, not a scoped key. It's the cost of a human-only allowlist on an external runner. Fine for a time-boxed lab; revoke after with gcloud auth application-default revoke and delete the secret. Production hardening: use Workload Identity Federation to an entitled service account in cloud-llm-preview1 instead — no human token in CI (needs that SA entitled to the codemender-preview agent).

Add the workflow & scripts

Commit .github/workflows/codemender.yml (Step 5) plus the four phase scripts under scripts/ — the same scripts as the Cloud Build lab, with two changes: cm-env.sh drops the gcsfuse mount (below), and everything else is identical (multi-file scan, _VERIFY_FANOUT / _FIX_FANOUT, per-worker independent clones).

4

Set the two secrets

ℹ The ADC must carry the quota project

You ran set-quota-project cloud-llm-preview1 in Step 1, so the JSON already has quota_project_id. The workflow also exports GOOGLE_CLOUD_QUOTA_PROJECT as belt-and-suspenders.

5

The workflow

Download cm, materialise the ADC, then run find (many files) → verify → fix → open one PR — all in one job.

⚠ Validated: fan-out is port-bound on a single-server target

Testing the Cloud Build scripts with a real binary showed two things. Parallel workers need independent clones (a git worktree shares .git and collides on index.lock). And cm verify/cm fix build & run Juice Shop on a fixed port (3000) to reproduce the exploit — so two in parallel collide on the port regardless of git isolation. For one app, keep VERIFY_FANOUT/FIX_FANOUT at 1, or fan out static verification with cm verify --skip-exploit-verification (no app, no port). The machinery scales; the single shared app is the limit.

Copy find.sh / verify.sh / fix.sh / open-pr.sh from the Cloud Build guide, Step 8 unchanged — they already use independent clones and read SCAN_PATH/*_FANOUT from the env set above.

6

Run it

⚠ If it fails on auth

Unsupported agent interaction: codemender-preview → your injected identity isn't entitled — re-check you signed in as @google.com and the quota project is cloud-llm-preview1. invalid_grant when minting the token → the ADC secret is stale; regenerate it (Step 1) and re-set CM_ADC.

7

Review, approve & merge

⚠ Preview terms: supervise it

Pre-GA CodeMender is for testing and evaluation, not production. The workflow disables interactive confirmations to run non-interactively; the human merge gate keeps a person in the loop.
